# Spec Delta

## Purpose

让读者能按正文内容找到文章：查询与索引使用同一套分词规则（包含连续中文），命中粒度到段落，结果按界面语言呈现并遵守与文章列表相同的语言回退规则，且完全在浏览器侧完成、不发出额外网络请求。

## ADDED Requirements

### Requirement: 查询匹配文章正文

搜索必须（MUST）匹配文章正文文本，而不只是标题、摘要和标签。查询词只出现在正文中的文章，也必须出现在结果里。

#### Scenario: 只出现在正文里的词

- **WHEN** 在 `/post?q=脚本目录` 搜索，而「脚本目录」只出现在某篇文章正文、不在其标题、摘要或标签中
- **THEN** 该文章出现在结果中

#### Scenario: 标题与正文同时命中时标题优先

- **WHEN** 一个查询词同时出现在文章 A 的标题和文章 B 的正文里
- **THEN** 两篇都出现在结果中，且 A 排在 B 前面

### Requirement: 中文查询与中文正文按同一规则切分

索引和查询必须（MUST）使用同一套分词规则，使不含空格的连续中文可以被检索到。查询不得（MUST NOT）因为「中文没有空格」而返回空结果。

#### Scenario: 连续中文查询

- **WHEN** 在 `/post?q=课件` 搜索，而某篇文章正文含「把课件、作业、指导增量下载到本地」
- **THEN** 该文章出现在结果中

#### Scenario: 中英混排查询

- **WHEN** 在 `/post?q=due.md` 搜索，而某篇文章正文含 `due.md`
- **THEN** 该文章出现在结果中

#### Scenario: 多词查询不要求连续

- **WHEN** 在 `/post?q=增量 下载` 搜索，而这两个词在同一篇文章正文中不相邻出现
- **THEN** 该文章出现在结果中

### Requirement: 命中粒度到段落且结果按文章聚合

搜索必须（MUST）能定位到文章内的具体段落，但结果列表必须（MUST）按文章聚合：同一篇文章在一次查询中只出现一次，并附带至少一个命中段落作为片段。片段必须（MUST）展示命中词附近的正文文本，而不是整段或整篇。

#### Scenario: 同一篇文章命中多个段落

- **WHEN** 一个查询词在同一篇文章的 3 个小节里都出现
- **THEN** 结果列表里该文章只占一行，并显示其中一个命中段落作为片段

#### Scenario: 片段来自命中处

- **WHEN** 结果行显示了某篇文章的片段
- **THEN** 片段中包含查询词（或其在正文中的分词结果），且只截取命中处附近的文本

### Requirement: 搜索遵守界面语言与正文回退规则

搜索结果必须（MUST）与文章列表使用同一套语言选择规则：优先界面语言对应的正文版本，缺少英文正文时回退中文正文。同一次查询不得（MUST NOT）把同一篇文章的中英两个版本同时列出。

#### Scenario: 英文界面缺英文正文

- **WHEN** 在 `/en/post?q=课件` 搜索，而该文章只有中文正文
- **THEN** 结果中出现该文章（标题为中文），且不出现重复的第二条

#### Scenario: 双语文章只出现一次

- **WHEN** 在 `/en/post?q=download` 搜索，而该文章同时有中英两个正文版本
- **THEN** 结果中该文章只出现一次，且展示的是英文版本

### Requirement: 查询状态由 URL 承载

当前查询必须（MUST）只由 `/post` 页面的 URL 查询参数 `q` 决定：刷新、分享、前进后退都必须还原同一份结果。空白或只有空格的 `q` 必须（MUST）被视为没有筛选，而不是无结果。

#### Scenario: 刷新与分享

- **WHEN** 打开 `/post?q=课件` 并刷新页面，或把该地址发给别人
- **THEN** 两边看到的是同一份结果

#### Scenario: 清空查询

- **WHEN** `q` 为空字符串或只有空格
- **THEN** 显示完整文章列表，不显示「无结果」空态

### Requirement: 搜索在浏览器侧完成

搜索必须（MUST）不依赖网络请求：首次打开 `/post` 之后，输入查询到出结果的过程中不得（MUST NOT）发出任何新的网络请求，站点在离线或只读静态部署下行为一致。

#### Scenario: 离线可用

- **WHEN** 页面加载完成后断网，再在搜索框输入查询词
- **THEN** 结果正常显示

### Requirement: 构建产物与正文不漂移

搜索数据必须（MUST）由文章正文在构建期派生，且与正文同源。正文变更而搜索数据未重新生成的状态必须（MUST）在 CI 中被判为失败。

#### Scenario: 改了正文忘了重新生成

- **WHEN** 修改了 `src/content/` 下的 MDX 但没有重新生成搜索数据就提交
- **THEN** CI 的构建检查失败并指出生成物有未提交的改动

#### Scenario: 索引覆盖全部公开文章

- **WHEN** 构建完成
- **THEN** 构建期生成的搜索数据覆盖 `src/content/` 下每一篇文章的每一个中英文正文版本
