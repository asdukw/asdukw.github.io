本章探讨批处理系统的设计与实现。从经典的 Unix 工具链（awk、sort、uniq 等）入手，说明排序、计数等基本批处理原语。

接着放大到分布式批处理系统。批处理式 I/O 以不可变、有界（bounded）的输入数据集为对象并生成输出，因而可以在不产生副作用的情况下重跑和调试。为处理文件，批处理框架主要由三部分组成：决定作业何时何地运行的编排层、持久化数据的存储层、实际处理数据的计算层。

我们了解了分布式文件系统与对象存储如何通过按块复制、缓存和元数据服务管理大文件，以及现代批处理框架如何通过可插拔 API 与它们交互；讨论了编排器如何在大型集群中调度任务、分配资源和处理故障，并比较了调度单个作业的编排器与管理一组依赖图作业整个生命周期的工作流编排器。

我们考察了几种批处理模型：先是 MapReduce 及其经典的 map、reduce 函数，随后转向 Spark、Flink 等数据流引擎——它们的数据流 API 更易用、性能更好。为理解作业如何扩展，还介绍了混洗（shuffle）算法，它是分组、连接、聚合的基础。随着系统成熟，关注点转向易用性：SQL 等高层查询语言与数据框 API 降低了门槛，查询优化器把声明式查询转成高效执行计划。

最后回顾四类常见用例：

- **ETL 数据管道**：通过定时工作流在不同系统间提取、转换、加载数据；
- **分析**：既支持预聚合的仪表板，也支持即席查询；
- **机器学习**：准备并处理大规模训练数据集；
- **用批处理输出填充线上系统**：通常经由流或批量加载工具，把衍生数据提供给用户。

下一章转向流处理：其输入是*无界的*（unbounded），作业依然存在，但输入是永无止境的数据流，任何时刻都可能有更多工作到来，作业永远不会完成。流处理与批处理在某些方面相似，但「流是无界的」这一假设会大幅改变系统的构建方式。
