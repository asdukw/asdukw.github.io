《设计数据密集型应用》（*Designing Data-Intensive Applications*，简称 DDIA）讲的是同一件事：当数据量、并发和故障都变成常态，怎么在众多方案里做出**有依据的权衡**。这本书不给标准答案，给的是判断依据。

这个系列是读书笔记，不是译本，也不是导读。规则只有一条：**跟着原书的小节走，一节一讲**。每篇的二级标题对应原书该节的三级标题，可译、不增删、不调换；正文只保留定义、机制、论证链和结论，书里的举例、轶事、参考文献和插图压成一两句或删掉。目的是复习时能顺着一页把一节重新走一遍，而不是再读一遍书。

正文依据的是 [DDIA 第二版中文翻译](https://ddia.vonng.com)，原文版权归作者 Martin Kleppmann 与译者所有，这里只做个人学习用的凝练。

书的缘起、目标读者与全书纲要见[序言](/notes/ddia/preface/)。

## 第一部分 · 数据系统基础

前五章讨论的是单机与分布式共用的底层概念，也是后面所有章节的地基。

- [1.1 分析型与事务型系统](/notes/ddia/chapter-01/lec-01/)——两类系统、数据仓库、数据湖，以及记录系统与衍生数据
- [2.1 案例研究：社交网络首页时间线](/notes/ddia/chapter-02/lec-01/)——用一个具体系统引出可靠性、可伸缩性、可维护性
- [3.1 关系模型与文档模型](/notes/ddia/chapter-03/lec-01/)——数据模型的历史，以及各自适用的场景
- [4.1 OLTP 系统的存储与索引](/notes/ddia/chapter-04/lec-01/)——B 树与 LSM 树，存储引擎如何决定读写代价
- [5.1 编码数据的格式](/notes/ddia/chapter-05/lec-01/)——序列化格式与模式演化，以及四种数据流

## 第二部分 · 分布式数据

单机的地基讲完，接着把数据放到多台机器上：为什么要分布、有哪几种伸缩架构，以及复制与分区两种分布机制。

- [第二部分 · 分布式数据](/notes/ddia/part-ii/)——伸缩的架构选择，以及复制与分区
- [6.1 单主复制](/notes/ddia/chapter-06/lec-01/)——领导者—追随者模型、同步与异步复制，以及三种复制日志实现
- [7.1 分片的利与弊](/notes/ddia/chapter-07/lec-01/)——分区键的取舍，以及用分片做多租户
- [8.1 事务到底是什么？](/notes/ddia/chapter-08/lec-01/)——ACID 的真实含义，与多对象事务的必要性
- [9.1 故障与部分失效](/notes/ddia/chapter-09/lec-01/)——分布式系统最根本的故障模型：部分失效
- [10.1 线性一致性](/notes/ddia/chapter-10/lec-01/)——表现得像单副本的新鲜度保证，以及 CAP 与延迟代价

## 第三部分 · 衍生数据

把多个不同的数据系统集成为一个协调的应用架构：记录系统与衍生系统的分工，以及批处理与流处理。

- [第三部分 · 衍生数据](/notes/ddia/part-iii/)——记录系统与衍生系统，以及本部分的结构
- [11.1 使用 Unix 工具的批处理](/notes/ddia/chapter-11/lec-01/)——用管道做日志分析，以及排序与内存聚合的取舍
- [12.1 传递事件流](/notes/ddia/chapter-12/lec-01/)——消息代理与基于日志的消息代理，以及无界事件流的传输
- [13.1 数据集成](/notes/ddia/chapter-13/lec-01/)——用衍生数据组合专用工具，以及全序的局限
- [14.1 预测分析](/notes/ddia/chapter-14/lec-01/)——算法决策的偏见、问责与反馈循环

## 阅读建议

- 第一次读按顺序走，第 3、4 章的概念会被后面反复引用。
- 只想回忆某一节时，从侧栏直接进对应篇目；每篇都尽量不依赖前文也能读懂。
- 书里的判断都有前提，笔记里保留了「在什么条件下成立」，别只记结论。
