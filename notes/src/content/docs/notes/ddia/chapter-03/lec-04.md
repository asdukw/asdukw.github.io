本章前面的数据模型既用于事务处理，也用于分析。还有一类模型常见于分析与科学场景，却很少出现在 OLTP 系统里：*数据框*（dataframe）和多维数值数组。

R、Python 的 pandas、Apache Spark、ArcticDB、Dask 都支持数据框。数据科学家用它准备机器学习训练数据，也用它做数据探索、统计分析和可视化。这些工作往往要反复试错：先看数据长什么样，再决定怎么筛、怎么补、怎么聚合，而不是执行一条预先定好的查询。

乍看之下，数据框很像关系表，也像电子表格。它支持一批类似关系运算符的操作：对所有行应用函数、按条件筛选、按列分组再聚合其他列、按键连接两个数据框（关系数据库里的*连接*，在数据框里通常叫*合并*，merge）。此外还有一批关系数据库没有、或写起来很别扭的操作，比如把行转成列。

差别更多在用法。数据框通常不用 SQL 这类声明式查询，而是一系列命令逐步改动结构与内容，这正好对应数据科学家的实际流程：一点点"整理"数据，直到它变成能回答当前问题的形状。这些操作一般发生在私有的数据副本上，常常就在本机，最终结果再分享给别人。

数据框 API 的许多操作超出关系数据库的能力，使用方式也常与关系建模大不相同。一种常见用途，是把关系式的数据转成矩阵或多维数组，而很多机器学习算法要的正是这种输入。例如用一张表记录用户对电影的评分（1 到 5 分），转成矩阵就是每列一部电影、每行一个用户，相当于电子表格里的*数据透视表*（pivot table）。这个矩阵是*稀疏*（sparse）的——大量用户与电影的组合没有数据——但这不影响使用，稀疏表示只存有值的条目；矩阵的列数随电影增长、行数随用户增长，很容易上万列，关系数据库要求列事先定义，显然不适合放它，数据框和 NumPy 这类支持稀疏数组的库处理起来却很轻松。

矩阵只能装数字，非数值数据得想办法转换：

- 日期可以按比例缩放成某个范围内的浮点数。
- 只取少数固定值的列（比如电影类型）用*独热编码*（one-hot encoding）：每个可能取值建一列，"喜剧""剧情""恐怖"各一列，代表某部电影的行在对应类型的列填 1，其余填 0；一部电影同时属于多个类型也能表达；代价是列数会随取值种类膨胀。

变成数值矩阵后就能做线性代数运算，而线性代数是许多机器学习算法的基础，比如用评分矩阵做电影推荐。数据框的灵活性就在这里：它让数据从关系形式逐步演化到矩阵表示，由数据科学家自己判断哪种表示适合当前的分析或训练目标——同一个数据集可以逐步从一张表变成矩阵，而不必先设计一套固定模式。

矩阵只是二维的情形；影像与观测数据常有三个甚至更多维度，比如空间坐标加时间。还有专门存储这类多维数值数组的数据库，例如 TileDB。这类系统叫*数组数据库*（array database），最常用于科学数据集——规则网格上的地理空间栅格、医学影像、天文望远镜的观测结果。这些数据维度固定、体量巨大，用数组模型比用表更自然。金融行业则用数据框表示*时间序列数据*（time-series data），如资产价格和按时间记录的交易。
