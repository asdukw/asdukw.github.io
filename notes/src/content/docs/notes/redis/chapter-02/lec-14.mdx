import { Tabs, TabItem } from '@astrojs/starlight/components';

向量集合（vector set）和有序集合（sorted set）结构上很像，区别在于元素不是带一个分数，而是带**一个向量**。往里加元素之后，可以做两类检索：

- 给一个查询向量，取最相似的一批元素；
- 给集合里已有的某个元素，取与它向量最相似的一批元素。

它还额外支持**带过滤的检索**：给元素挂上属性，然后在 `VSIM` 里用 `FILTER` 选项对这些属性做简单数学判断，比如 `".year > 1950"`，一边算相似度一边筛。

和 Time series 一样，这不是内置类型，属于 Redis Stack / Redis 8 的模块能力，命令族是 `VADD` / `VSIM` / `VCARD` / `VDIM` / `VEMB` / `VREM` / `VSETATTR` / `VGETATTR`。

## FP32 的字节序注意事项

`VADD`、`VSIM` 这些命令接受 FP32 的二进制 blob，这个 blob **必须是小端字节序（little-endian）**。原因是跨平台兼容：部分 ARM 变体和其他架构可能用不同的字节序。

如果你的平台是大端或混合端，两条路：

- 传之前手动把字节序转成小端；
- 改用 `VALUES` 语法——它接受字符串形式的浮点数，与平台字节序无关。

日常在 x86 / 常规 ARM 上用 `VALUES` 写例子最省事，这也是下面所有示例的写法；只有在批量导入预先算好的 embedding 二进制时才会落到 blob 和小端问题上。

## 示例

官方的例子刻意用**二维向量**，把点摆在笛卡尔平面上好理解：A `(1.0, 1.0)`、B `(-1.0, -1.0)`、C `(-1.0, 1.0)`、D `(1.0, -1.0)`、E `(1.0, 0)`。

但真实场景里，向量通常是**文本 embedding，维度是几百**。二维只是为了画图和手算方便，命令用法与维度无关——除了 `VALUES` 后面那个维度数字要跟着改。

### Basic operations

`VADD` 建集合并写入第一个元素（集合对象是隐式创建的）。写完 `TYPE` 会返回 `vectorset`：

<Tabs syncKey="redis-client">
<TabItem label="redis-cli">

```bash
> VADD points VALUES 2 1.0 1.0 pt:A
(integer) 1
> VADD points VALUES 2 -1.0 -1.0 pt:B
(integer) 1
> VADD points VALUES 2 -1.0 1.0 pt:C
(integer) 1
> VADD points VALUES 2 1.0 -1.0 pt:D
(integer) 1
> VADD points VALUES 2 1.0 0 pt:E
(integer) 1
> TYPE points
vectorset
```

</TabItem>
<TabItem label="Python">

```python
import redis

r = redis.Redis(host="localhost", port=6379, decode_responses=True)

for name, vec in {
    "pt:A": (1.0, 1.0),
    "pt:B": (-1.0, -1.0),
    "pt:C": (-1.0, 1.0),
    "pt:D": (1.0, -1.0),
    "pt:E": (1.0, 0.0),
}.items():
    r.execute_command("VADD", "points", "VALUES", 2, *vec, name)

r.type("points")   # 'vectorset'
```

</TabItem>
</Tabs>

`VALUES 2` 里的 `2` 就是维度：这条集合一旦建立，**所有元素的维度必须一致**。

`VCARD` 取元素个数（基数），`VDIM` 取向量维度：

<Tabs syncKey="redis-client">
<TabItem label="redis-cli">

```bash
> VCARD points
(integer) 5
> VDIM points
(integer) 2
```

</TabItem>
<TabItem label="Python">

```python
r.execute_command("VCARD", "points")   # 5
r.execute_command("VDIM", "points")    # 2
```

</TabItem>
</Tabs>

`VEMB` 按元素名取回向量。注意返回值**一般不会等于你写进去的精确值**——为了性能做了量化（quantization），`1.0` 读回来是 `0.9999999403953552` 这种：

<Tabs syncKey="redis-client">
<TabItem label="redis-cli">

```bash
> VEMB points pt:A
1) "0.9999999403953552"
2) "0.9999999403953552"
> VEMB points pt:E
1) "1"
2) "0"
```

</TabItem>
<TabItem label="Python">

```python
r.execute_command("VEMB", "points", "pt:A")
# ['0.9999999403953552', '0.9999999403953552']
r.execute_command("VEMB", "points", "pt:E")
# ['1', '0']
```

</TabItem>
</Tabs>

这个误差不是 bug，是设计取舍：向量集合靠量化压缩存储来做快速检索，所以「写进去的值」和「读回来的值」只在近似意义上相等。做数值校验时别用精确比较。

`VREM` 删元素：

<Tabs syncKey="redis-client">
<TabItem label="redis-cli">

```bash
> VADD points VALUES 2 0 0 pt:F
(integer) 1
> VCARD points
(integer) 6
> VREM points pt:F
(integer) 1
> VCARD points
(integer) 5
```

</TabItem>
<TabItem label="Python">

```python
r.execute_command("VADD", "points", "VALUES", 2, 0, 0, "pt:F")   # 1
r.execute_command("VCARD", "points")                              # 6
r.execute_command("VREM", "points", "pt:F")                       # 1
r.execute_command("VCARD", "points")                              # 5
```

</TabItem>
</Tabs>

属性是一段 JSON 字符串，用 `VSETATTR` 写、`VGETATTR` 读。给 `VSETATTR` 传空字符串就是**删除**属性：

<Tabs syncKey="redis-client">
<TabItem label="redis-cli">

```bash
> VSETATTR points pt:A "{\"name\": \"Point A\", \"description\": \"First point added\"}"
(integer) 1
> VGETATTR points pt:A
"{\"name\": \"Point A\", \"description\": \"First point added\"}"
> VSETATTR points pt:A ""
(integer) 1
> VGETATTR points pt:A
(nil)
```

</TabItem>
<TabItem label="Python">

```python
import json

r.execute_command(
    "VSETATTR", "points", "pt:A",
    json.dumps({"name": "Point A", "description": "First point added"}),
)
r.execute_command("VGETATTR", "points", "pt:A")   # JSON 字符串

r.execute_command("VSETATTR", "points", "pt:A", "")
r.execute_command("VGETATTR", "points", "pt:A")   # None
```

</TabItem>
</Tabs>

属性是**整个元素上的一段 JSON**，不是多字段；更新就是整段覆盖。

### Vector similarity search

`VSIM` 按与查询向量的距离排序返回元素。最简形式直接给向量：

<Tabs syncKey="redis-client">
<TabItem label="redis-cli">

```bash
> VSIM points values 2 0.9 0.1
1) "pt:E"
2) "pt:A"
3) "pt:D"
4) "pt:C"
5) "pt:B"
```

</TabItem>
<TabItem label="Python">

```python
r.execute_command("VSIM", "points", "values", 2, 0.9, 0.1)
# ['pt:E', 'pt:A', 'pt:D', 'pt:C', 'pt:B']
```

</TabItem>
</Tabs>

也可以不传向量，用 `ELE` 指定集合里已有的元素当查询点：

<Tabs syncKey="redis-client">
<TabItem label="redis-cli">

```bash
# 离 A 最近的 4 个，带分数
> VSIM points ELE pt:A WITHSCORES COUNT 4
1) "pt:A"
2) "1"
3) "pt:E"
4) "0.8535534143447876"
5) "pt:C"
6) "0.5"
7) "pt:D"
8) "0.5"
```

</TabItem>
<TabItem label="Python">

```python
r.execute_command("VSIM", "points", "ELE", "pt:A", "WITHSCORES", "COUNT", 4)
# ['pt:A', '1', 'pt:E', '0.8535534143447876',
#  'pt:C', '0.5', 'pt:D', '0.5']
```

</TabItem>
</Tabs>

**返回结构**这块要分清两种形状：

- 不加 `WITHSCORES`：扁平数组，只有元素名，顺序即距离从近到远。
- 加 `WITHSCORES`：仍是扁平数组，但**元素名和分数交替出现**（`[名, 分, 名, 分, ...]`），不是一个 `{名: 分}` 的映射。要转成字典得自己按 2 步长切。

分数是**相似度**，不是距离：`1` 表示完全一致（自己跟自己永远是 1），数值越大越相似，所以返回顺序是分数从大到小。`COUNT` 限制返回条数，不写就是全部。

最后是 `FILTER`。先给元素挂上 JSON 属性，再在检索时写表达式：

<Tabs syncKey="redis-client">
<TabItem label="redis-cli">

```bash
> VSETATTR points pt:A "{\"size\":\"large\",\"price\": 18.99}"
(integer) 1
> VSETATTR points pt:B "{\"size\":\"large\",\"price\": 35.99}"
(integer) 1
> VSETATTR points pt:C "{\"size\":\"large\",\"price\": 25.99}"
(integer) 1
> VSETATTR points pt:D "{\"size\":\"small\",\"price\": 21.00}"
(integer) 1
> VSETATTR points pt:E "{\"size\":\"small\",\"price\": 17.75}"
(integer) 1

# 离 A 最近、且 size 为 large 的元素
> VSIM points ELE pt:A FILTER '.size == "large"'
1) "pt:A"
2) "pt:C"
3) "pt:B"

# 再加一个数值条件
> VSIM points ELE pt:A FILTER '.size == "large" && .price > 20.00'
1) "pt:C"
2) "pt:B"
```

</TabItem>
<TabItem label="Python">

```python
for name, attrs in {
    "pt:A": {"size": "large", "price": 18.99},
    "pt:B": {"size": "large", "price": 35.99},
    "pt:C": {"size": "large", "price": 25.99},
    "pt:D": {"size": "small", "price": 21.00},
    "pt:E": {"size": "small", "price": 17.75},
}.items():
    r.execute_command("VSETATTR", "points", name, json.dumps(attrs))

r.execute_command("VSIM", "points", "ELE", "pt:A",
                  "FILTER", '.size == "large"')
# ['pt:A', 'pt:C', 'pt:B']

r.execute_command("VSIM", "points", "ELE", "pt:A",
                  "FILTER", '.size == "large" && .price > 20.00')
# ['pt:C', 'pt:B']
```

</TabItem>
</Tabs>

表达式语法是「属性名以 `.` 开头」，字符串用双引号，多个条件用 `&&` 连接。没有挂属性的元素在需要该属性的条件里自然被排除。

> **关于维度与数量上限**：这一页只讲了 FP32 存储、小端字节序和量化带来的近似，并没有给出维度上限、元素数量上限这类数值。具体性能参数和限制在官方本节的其他页面里（量化效应、性能参数），这里不臆造数字。
