Redis 的字符串存的是**字节序列**——可以是文本、序列化后的对象（JSON / MessagePack），也可以是二进制数组，比如一张 jpeg 图片。它是最简单的一种值类型，常被用来做缓存，但除此之外还支持计数器和位运算。

因为 Redis 的 key 本身就是字符串，所以「字符串 → 字符串」的映射是它最原始的形态。

## 基础用法

<Tabs syncKey="redis-client">
<TabItem label="redis-cli">

```bash
> SET bike:1 Deimos
OK
> GET bike:1
"Deimos"
```

</TabItem>
<TabItem label="Python">

```python
import redis

r = redis.Redis(host="localhost", port=6379, decode_responses=True)

r.set("bike:1", "Deimos")   # True
r.get("bike:1")             # 'Deimos'
```

</TabItem>
</Tabs>

Python 侧统一用 redis-py（`pip install redis`），后续示例沿用这个 `r`。`decode_responses=True` 是为了拿到 `str` 而不是 `bytes`。

注意 `SET` 是**赋值**：哪怕 key 上原来存的是别的类型，也会被直接覆盖，不报错、不合并。

### SET 的选项

`SET` 的附加参数决定了它的条件语义，日常最重要的是 `NX` 和 `XX`：

<Tabs syncKey="redis-client">
<TabItem label="redis-cli">

```bash
# 先把它复原，让例子可以单独运行
> SET bike:1 Deimos
OK
> SET bike:1 bike NX     # key 已存在，NX 失败
(nil)
> SET bike:1 bike XX     # key 存在，XX 成功
OK
```

</TabItem>
<TabItem label="Python">

```python
r.set("bike:1", "Deimos")
r.set("bike:1", "bike", nx=True)   # None，因为 key 已存在
r.set("bike:1", "bike", xx=True)   # True，因为 key 存在
```

</TabItem>
</Tabs>

单个 value 的大小上限是 **512 MB**，这是硬限制。

### 8.4 新增：写前比较（CAS / CAD）

从 Redis 8.4 起，`SET` 可以在写入前检查 key 当前的值。`IFEQ` 表示「当前值等于这个才写」，也就是 compare-and-swap；`DELEX` 把同样的判断用到删除上，即 compare-and-delete：

<Tabs syncKey="redis-client">
<TabItem label="redis-cli">

```bash
> SET bike:1 Deimos
OK
> SET bike:1 Ares IFEQ Deimos    # 值没变，写入成功
OK
> SET bike:1 Zeus IFEQ Deimos    # 值已是 Ares，条件不满足
(nil)
> GET bike:1
"Ares"
> DELEX bike:1 IFEQ Deimos       # 当前值是 Ares，删不掉
(integer) 0
> DELEX bike:1 IFEQ Ares
(integer) 1
```

</TabItem>
<TabItem label="Python">

```python
# redis-py 8.x 已直接支持 ifeq / delex；旧版本可用 execute_command 发原始命令
r.set("bike:1", "Deimos")
r.set("bike:1", "Ares", ifeq="Deimos")    # True
r.set("bike:1", "Zeus", ifeq="Deimos")    # None
r.get("bike:1")                           # 'Ares'
r.delex("bike:1", ifeq="Deimos")          # 0
r.delex("bike:1", ifeq="Ares")            # 1
```

</TabItem>
</Tabs>

`IFNE` 是反向判断；`IFDEQ` / `IFDNE` 比较的不是原值而是值的哈希摘要，摘要用 `DIGEST` 取（XXH3）。这几个都需要 **Redis 8.4+**。

### 其他常用命令

`GETSET` 一次性完成「写新值 + 返回旧值」。典型场景：用 `INCR` 累计访问量，每小时结算一次并归零，又不想丢掉期间的增量——`GETSET key 0` 正好。

`MSET` / `MGET` 则用来在一次往返里读写多个 key：

<Tabs syncKey="redis-client">
<TabItem label="redis-cli">

```bash
> MSET bike:1 "Deimos" bike:2 "Ares" bike:3 "Vanth"
OK
> MGET bike:1 bike:2 bike:3
1) "Deimos"
2) "Ares"
3) "Vanth"
```

</TabItem>
<TabItem label="Python">

```python
r.mset({"bike:1": "Deimos", "bike:2": "Ares", "bike:3": "Vanth"})
r.mget(["bike:1", "bike:2", "bike:3"])   # ['Deimos', 'Ares', 'Vanth']
```

</TabItem>
</Tabs>

## 计数器

字符串只要能解析成整数，就能用 `INCR` / `INCRBY` / `DECR` / `DECRBY` 做原子加减；key 不存在时按 0 起算。

<Tabs syncKey="redis-client">
<TabItem label="redis-cli">

```bash
> SET total_crashes 0
OK
> INCR total_crashes
(integer) 1
> INCRBY total_crashes 10
(integer) 11
```

</TabItem>
<TabItem label="Python">

```python
r.set("total_crashes", 0)
r.incr("total_crashes")         # 1
r.incrby("total_crashes", 10)   # 11
```

</TabItem>
</Tabs>

「原子」在这里的含义很具体：多个客户端同时对同一个 key 执行 `INCR`，不会出现「都读到 10、都写回 11」的竞争。读-加-写这一串在 Redis 里是作为一个整体执行的。

## 上限

单个字符串最大 **512 MB**。这是硬上限，不是建议值。

## 位与位域操作

字符串可以按位操作，也可以在一个字符串里切出多个整数位段。这两块内容各自成篇：

- 位图（Bitmaps）：`SETBIT` / `GETBIT` / `BITCOUNT` / `BITOP`，用于签到、UV 去重这类场景。
- 位域（Bitfields）：`BITFIELD`，在一个字符串里读写任意位宽和偏移的整数。

## 性能

绝大多数字符串操作是 **O(1)**。需要小心的是 `SUBSTR`、`GETRANGE`、`SETRANGE`——它们做随机访问，复杂度可能退化成 **O(n)**，在超大字符串上频繁调用会出问题。

## 替代方案

如果你是把结构化数据整体序列化成一个字符串，读改任一字段都要整块取出再写回，这时更合适的是 [Hash](/notes/redis/chapter-02/lec-06/) 或 [JSON](/notes/redis/chapter-02/lec-07/)。
